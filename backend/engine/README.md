# BTC 五分钟反转交易底座

本目录只维护 Polymarket BTC Up/Down 五分钟反转策略的实时交易底座。生产入口只有 `dist/cli/platform.js`，策略通过 `StrategyPlugin` 接口接入，行情使用 Polymarket CLOB Market WebSocket，账户订单和成交使用认证 User WebSocket；REST 只用于市场发现、规则预热、异常恢复、账户对账和结算。

公网控制台为 https://34-242-206-196.sslip.io/console/。真实交易进程必须由用户在控制台明确启动。

平台命令要求显式 `--live`，没有模拟执行入口：

```powershell
node dist/cli/platform.js --live --strategy btc-reversal --strategy-config results/dashboard/btc-reversal-config.json --duration-sec 0
```

策略配置由控制台保存。修改参数只影响下一场，当前订单继续按创建时的版本管理。关闭网页不会停止运行，停止和暂停通过控制台发起。

## 本会话负责范围

| 功能 | 是否需要实时行情 | 运行时依赖 |
| --- | --- | --- |
| BTC 五分钟场次识别、阶段判断和反转信号 | 是 | 当前场次的 Up/Down 双边盘口、行情时间戳、新鲜度和时间偏差 |
| 阶段资金预留和同方向去重 | 否（由信号触发） | 当前账户余额、持仓、未完成订单和费用规则 |
| 下单、撤单、订单幂等和未知结果隔离 | 否（由信号或控制事件触发） | CLOB 签名/HTTP、认证 User WebSocket、恢复查询 |
| 启动、暂停、停止和最终状态事件 | 否 | 控制文件或控制台命令、平台状态机 |
| 重启恢复、成交入账和场次结束结算触发 | 否 | 持久化状态、账户快照、User WebSocket、结算适配器 |

慢资金流扫描、历史查询、胜率统计、资源采样和结算到账核对不在实时下单路径中。它们只能更新账户覆盖或结算状态，不能让一个已经形成的实时信号等待慢查询。

## 实时数据边界

- **必须对接行情**：CLOB Market WebSocket 的当前 BTC 五分钟市场双边盘口。策略只消费当前场次的 Up/Down `Book`，要求两边报价新鲜、时间戳可排序且时间偏差在配置范围内；行情断线或恢复时会先清空基线，避免用断线期间的旧报价推断跨价。
- **必须对接交易回报**：认证 User WebSocket 的订单、成交和撤单事件。它们用于更新订单最终状态、释放预留、记录成交和解除恢复闸门，不用于产生价格信号。
- **启动时需要但不进入热路径**：市场发现、token、tick size、最小数量和费用规则。平台会在首单前预热这些规则，实时信号不会查询历史数据。
- **恢复时使用**：REST 账户快照、未结订单、订单详情和近期成交。恢复读取期间只锁住有未确认订单的市场；其他当前场次仍可消费实时行情。
- `--reference-feed` 仅提供外部 BTC 价格遥测，策略不依赖它，也不会用它替代 CLOB 双边盘口。

## 阶段和订单规则

第一份完整双边盘口只建立基线，不直接下单。只有观察到一侧从低于 `triggerPrice` 真正上穿到触发价以上，才创建下一阶段的经济订单意图；双边同一帧同时上穿会进入歧义状态，等待下一次明确方向。如果一侧已经处于高价区，另一侧随后新跨过触发价，则按反转信号处理。

`maxBuyPrice` 是实际 BUY 限价，`confirmationPrice` 只更新方向确认和 `confirmationCount`，当前不会延迟下一阶段下单。新创建的阶段统一使用 `trigger: "crossing"`；旧持久化状态中的 `initial_band_entry` 只为读取兼容保留。

策略在返回提交动作前先把 `clientOrderId` 和阶段写入持久化状态。平台按经济订单键幂等，提交、查回、撤单和重试保持串行；HTTP 超时或进程重启后的订单会进入 `UNKNOWN`/恢复闸门，不会生成一个补偿性新订单。场次结束时仍为 `CREATED` 的未提交意图会标记为 `ABANDONED`，已有订单身份的余单进入撤单流程。

暂停会阻止新增阶段但保留恢复和成交处理。停止会停止行情和用户订阅，逐单处理未完成订单，并无论撤单或对账是否出现错误都发布最终 `stopped` 事件；失败结果会保留在风险状态中供下一次恢复处理。

不同订单可以并行提交；同一经济订单的提交、查回、撤单和重试保持串行。交易决策由 WebSocket 事件直接触发，不使用固定秒级采样、debounce 或 REST 盘口轮询。页面展示消息年龄、本地处理、签名、HTTP ACK、用户回报和撤单 ACK 的分段延迟，缺少真实样本时显示未知。

新经济订单统一经过 `ClobWrapper.submitOrder()`，策略不直接调用 CLOB SDK；恢复只会通过 `resubmitPrepared()` 重放已经持久化的签名订单，不会生成新的经济订单。BUY/SELL、GTC/FOK/FAK 和逐单撤单仍由底座支持；旧的金额换算买单、FOK 市价卖单、单独 tick 查询、全量撤单等未使用便捷入口已移除。

账户秘密、真实订单/成交/资金/结算数据不放入发布包。程序发布采用本地源码、Git 提交、服务器发布目录三段校验，并保留可回退版本；回退程序不会覆盖之后产生的交易账本。
