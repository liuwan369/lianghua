# 测试与验收

自动测试验证软件行为，真实验收验证交易所和链上的实际结果。两者必须分别记录。

## 统一离线验证

在仓库根目录运行：

```powershell
python scripts/verify-project.py
```

脚本依次记录 Git/运行环境、Python 测试、引擎测试与构建、前端测试与构建，并把日志和哈希写入 `.planning/tmp/verification/<run_id>/manifest.json`。它不读取真实交易秘密，不会下单、撤单、赎回或转账。

模块命令：

```powershell
python -m pytest -q
npm --prefix _external/btc-5m-market-trading-bot run typecheck
npm --prefix _external/btc-5m-market-trading-bot test
npm --prefix _external/btc-5m-market-trading-bot run build
npm --prefix web test
npm --prefix web run build
git diff --check
```

## 必测软件行为

- 同一 Market WS 消息原子应用两侧盘口，只触发一次策略判断。
- `best_bid_ask`、完整 L2、同毫秒变化、空盘口、断线和重连时序。
- 双边同时触发的 `pendingAmbiguity` 与后续方向解析。
- 重连只重建基线，不补造断线期间订单。
- 不同订单并行、同一订单去重串行，以及等待锁后的预算/余额二次检查。
- 提交未知、明确拒单、部分成交、撤单竞态、迟到成交和终态恢复。
- 当前有效持仓与已结算零价值历史残留的分类。
- 延迟样本绑定当前 `run_id`、15 秒过期、无样本显示未知。
- CPU、内存、磁盘、负载和关键进程身份。
- 订单固定快照分页在新事件进入后不重复、不漏单。

网络边界用替身的测试证明本地状态变换和调用顺序，不证明 Polymarket 已接受真实订单，也不代表公网延迟。

## 部署后只读验收

发布后核对：

1. 本地提交、远端提交和服务器发布清单一致。
2. 控制台及主读取 API 返回 200，静态资源没有旧 hash。
3. `running`、PID、命令行、`run_id` 和策略投影互相一致。
4. 未启动时开放订单为 0，当前有效持仓口径与账户真实状态一致。
5. 总览显示服务器指标；没有当前样本的延迟保持未知。
6. 桌面和手机布局无溢出，订单分页和策略配置可用。

这些检查不产生金融操作。

## 小额真实验收

真实操作由用户在控制台发起，阶段份额使用临时 `[5,5,5,5]`。系统随后必须留下可核对证据：

1. Market WS 触发时间、决策时间、HTTP 发出和订单 ACK。
2. 交易所订单 ID、认证 User WS 事件、成交价格/份额和实际费用。
3. 撤单请求、撤单 ACK、在途成交核对和最终开放订单。
4. 重启后同一订单、预留、持仓和阶段恢复，无重复经济请求。
5. 自动换场时新场使用正确配置，旧场继续收尾。
6. 结算成功回执、资产转移、持仓清零和实际到账。

真实证据缺一项就只标记对应项未完成，不新增多日 paper、午夜基线、第三日期或固定历史额度作为等待条件。真实成交只能证明功能链路，不证明策略盈利。
