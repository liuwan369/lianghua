# 项目上下文

更新时间：2026-09-07（都柏林节点迁移与测速更新）

## 目标

维护一个普通用户可操作的 Polymarket BTC Up/Down 5 分钟双边动态补仓系统。当前主节点为 AWS 都柏林，先用真实公开数据完成采集、回放和纸面模拟；真实订单、返佣和奖励放最后。

## 当前事实

- 目标地址研究对象：`0x3048d65321be3497164cdfc2996f94f98a2e7537`。
- 公开行为结论：主要是 BTC 5 分钟市场双边买入，成交后补较轻的一边，不代表每场都锁定盈利。
- 当前策略：先算配对成本和单边风险，再按当前赔率动态计算补仓数量；价格无法修复时停止追价。
- 都柏林采集器记录公开盘口、公开成交、BTC 行情、市场元数据和 Polygon 链上成交日志；旧东京数据仅作线路对照。
- 页面只显示三个入口：交易、配置、订单。
- Polymarket 账户已注册并可登录；当前现金/组合约约为 `$17.13`，没有持仓。
- 登录方式已确认：邮箱登录；底层签名类型和交易钱包待入金后只读预检确认。
- 当前未创建 Relayer API 密钥，页面也显示该账户不支持会话密钥；尚未进行任何授权下单。

## 真实性边界

- 公开行情和东京采集是真实数据。
- 纸面成交、成交概率、排队量和模拟收益是模型结果，不能当作真实账户结果。
- 返佣、流动性奖励和 maker/taker 费用没有逐笔账户证据时按 0 计算。
- 没有官方结算价时保持未结算，不用盘口猜输赢。

## 代码边界

- 主引擎：`_external/btc-5m-market-trading-bot`。
- 影子回放：`pm_maker`、`scripts/pm-r26-historical-shadow-replay.py`、`scripts/pm-r27-parameter-sweep.py`、`scripts/pm-r28-risk-sweep.py`。
- 采集器：`scripts/pm-r25-tokyo-evidence-collector.py`（由都柏林配置调用）。
- 页面服务：`scripts/system-dashboard-server.py`。
- 当前默认 `trade_authorization=false`，禁止真钱下单。
