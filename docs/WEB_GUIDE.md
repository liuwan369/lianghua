## 设置保存

以下六项可以保存到服务器，下次启动生效：

| 项目 | 服务端字段 |
|---|---|
| 单笔金额 | `order_usd` |
| 挂单寿命 | `maker_life_sec` |
| 运行模式 | `mode` |
| 运行时长 | `duration_min` |
| 累计提交金额上限 | `max_total_usd` |
| 订单数上限 | `max_orders` |

其余高级输入仅是当前页草稿，轮询不覆盖编辑，刷新会丢弃，点击保存不会令其生效。保存成功应出现配置版本及“下次启动生效”反馈。409 表示另一个保存改变了版本，需要重新核对配置；失败时草稿保留。选择 live 只是保存运行模式，不解锁、不启动交易。

## 账户检查与保存

在设置的账户区域输入资金钱包地址、Owner 签名私钥及需要的可选 Relayer 配置，通过当前 HTTPS 页面提交。私钥不应粘贴到聊天或日志。

“检查”执行只读验证；“保存账户”检查成功后才写入服务器。检查成功不能代替保存。成功检查或保存后敏感输入会清空且不回显；若检查的是新密钥，随后保存须重新输入。空白密钥不会把服务器密钥显示到页面。以明确的“保存成功”反馈和脱敏账户状态确认结果。

检查失败不会覆盖原有账户配置。400 类校验错误需要核对输入；429 表示已有检查在执行；502/503/504 可能来自上游不可用、启动失败或超时，应结合具体错误信息处理。2026-09-10 都柏林在 paper 负载下仍观察到账户超时，不能把所有失败都归因于 key。

## 盘口与交易状态

市场切换时可能短暂只有单边报价；页面应显示无效或不可用状态，不能拼接其他市场/过期报价。若长时间无有效盘口，应检查采集服务、市场 token、数据时间戳及资源负载。

真实交易尚未通过端到端验收，页面启停/退出禁用。实际 V2 账户授权与私有查询通过，只证明相应只读能力。完整待办和带时间戳的验证见 [DELIVERY.md](DELIVERY.md)。
