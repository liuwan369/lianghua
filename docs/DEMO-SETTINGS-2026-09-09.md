原六页设计基线为提交 `269f8ab`、标签 `ui-demo-2026-09-09`。策略/运行表单资源为 `docs/demo-settings.js/css`，正式接线位于 `web/src/forms.ts`。保持基础、高级、运行、账户、系统诊断、收益及延迟模块和完整布局。

## 设计分组

基础设置包括策略本金、每笔金额、单场占用、目标成本、硬上限、未配对份数、挂单时限、补仓等待、开仓/补仓截止。高级折叠包括单双档、价差、补仓失败处理、滑点和风险处置损失限制。运行设置包括模式、时长、累计提交金额/订单数、日亏损线、并发场数、断线/过期/停止持仓处理与生效时间。

账户秘密不写入浏览器策略草稿，不回显服务器原值。正式配置以服务器版本为准；原设计的本地预览不能当作已生效交易配置。

## 正式字段映射

| 原设计字段 | 服务器字段 | 含义 |
| --- | --- | --- |
| order | order_usd | 每次委托名义金额上限，实际费用另受预算约束 |
| life | maker_life_sec | 挂单寿命秒数，撤单确认前仍有占用 |
| mode | mode | 模式，纸面控制可用；保存 live 不解锁实盘 |
| duration | duration_min | 运行时长分钟，0 表示无期限 |
| submitted | max_total_usd | 累计提交金额保险丝，不因撤单恢复 |
| maxOrders | max_orders | 累计提交订单数上限 |
| pairCost | pair_cost_max | 现有引擎配对/加仓成本参数，不等于补仓硬上限 |
| decisionInterval | decision_interval_ms | 最短决策间隔，0 不节流 |
| defensiveCancel | defensive_cancel_bps | BTC 逆向波动撤单阈值，0 关闭 |

其他原设计字段仍是明确标注的草稿，不保存到服务器或影响引擎。后端已有的 `pair_cost_max` 等字段不表示原设计相似输入框已经接线。

## 数值与风控口径

- 单场占用要同时计持仓成本、有效挂单和费用预留，未结算资金不可重复使用。
- 原设计自动未配对份数公式 `floor(单场预算 / 配对硬上限)` 仅是草稿估算，不是已验证最优库存模型。
- 最低份数来自真实市场，不用演示价格 0.50 或固定 5 份替代；不足最低委托时拒绝，不自动增量。
- 停止并撤单不等于卖出持仓，断线不保证撤单成功，损失停止线不保证最终亏损封顶。
- 运行中保存应显示下次生效；下一场热更新、全量高级动作尚未完成前端闭环，不得标记已生效。
- 原设计校验及试算不接真实资金，不生成伪造成交或收益。

每个字段必须完成保存、重读、运行快照和行为证据后才能从草稿改为已接入。完整清单见 [前端接入验收](FRONTEND-INTEGRATION-PLAN.md)。
