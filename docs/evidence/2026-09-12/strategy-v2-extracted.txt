


    
    Polymarket 5分钟BTC/ETH做市机器人 — 完整策略方案（v2.0 完善版）

    本文档基于Polymarket平台2026年最新机制编写，涵盖策略逻辑、平台机制、风控规则、技术架构、数据佐证及部署运维。可直接交付给AI开发人员作为编码依据。

    

    
    一、项目概述

    
    1.1 项目目标

    开发一套自动化做市机器人（Market Making Bot），在 Polymarket 平台的 5分钟 BTC/ETH 涨跌预测市场 中，通过双边挂单提供流动性，赚取买卖价差（Spread）+ Taker手续费返佣（Rebates）+ 平台LP奖励（Liquidity Rewards），同时通过严格的风控模块控制逆向选择风险。

    
    
    1.2 策略定位

    本策略属于 纯做市商（Pure Market Maker） 模式，核心特征是：

    不做方向性预测，不赌涨跌

    只做流动性提供者（Maker），不做流动性消耗者（Taker）

    通过库存管理保持 Delta 中性（双边持仓平衡）

    利润来源：价差 + 返佣 + LP奖励，而非方向判断

    策略定位核心指令（必须写进代码注释）：

    我们是 Maker（挂单方），不是 Taker（吃单方）。20ms 延迟对于 Maker 策略完全足够。代码的优化重点是订单管理的稳定性，而不是追求极致的抢单速度。我们的目标是最大化挂单时间和挂单量，以赚取返佣和奖励，价差是次要的。

    
    
    1.3 为什么这是最优策略

    根据2026年Polymarket平台最新机制：

    2026年1月起引入动态Taker手续费（概率50%时最高达1.75%）

    移除了500毫秒Taker延迟，普通用户无法靠延迟套利赚钱

    Maker免手续费且获得Taker手续费的20%-25%返佣

    平台推出LP奖励计划，挂单即赚钱（无需成交）

    持仓奖励年化4%，资金放在平台也能生息

    结论：在当前的平台机制下，做市商是唯一可持续盈利的策略。方向性预测、延迟套利、Taker动量等策略经实测胜率极低或盈亏比为负。

    

    
    
    
    二、Polymarket 平台机制详解

    
    2.1 二元合约机制

    每个预测问题设计为 YES/NO 二元合约

    YES价格 + NO价格 = 1美元（理论恒等式）

    结算时，赢的一方每股获得1美元，输的一方归零

    价格范围：0 ~ 1美元

    价格即市场认为该事件发生的概率

    2.4 流动性激励（LP Rewards）

    不需要订单成交，只要挂在订单簿上提供流动性就能赚钱

    每个市场定义最大激励价差（如正负4美分）

    平台每分钟采样订单簿，计算距离中点的距离得分

    双边报价（YES+NO同时挂）得分更高，单边报价受惩罚

    每日午夜以USDC发放，最低1美元起付

    
    
    2.5 持仓奖励（Holding Rewards）

    符合条件的持仓按年化4.00%利率计算

    公式：每小时奖励 = 持仓总价值 x (0.04 / 365 / 24)

    每日自动发放，由Polymarket国库出资

    
    
    2.6 盈利总公式

    总利润 = 买卖价差(Spread) + Taker手续费返佣(Rebates) + 平台LP奖励(Liquidity Rewards) + 持仓奖励(Holding Rewards) - 逆向选择亏损(Adverse Selection) - 止损损失

    三、核心策略逻辑

    
    3.1 策略核心思想

    在YES和NO两侧同时挂限价买单（Maker），赚取：

    价差：买入价与卖出价之间的差额

    返佣：当对方Taker吃掉你的单子时，你获得返佣

    LP奖励：只要挂单在奖励区内，即使不成交也有奖励

    
    
    3.2 挂单逻辑

    中间价(Mid Price) = (最高买价Bid + 最低卖价Ask) / 2

    买入价(Bid) = Mid Price - 设定价差(Spread/2) 卖出价(Ask) = Mid Price + 设定价差(Spread/2)

    示例：

    Mid Price = 0.50 Spread = 0.02

    挂买单 Buy YES @ 0.49 (Maker)

    挂卖单 Sell YES @ 0.51 (Maker) 等价于：Buy YES @ 0.49 + Sell NO @ 0.49

    3.4 为什么补仓不是好策略

    在5分钟市场中，当你一边成交后试图去补另一边时：

    非原子执行风险：两笔订单独立撮合，第一笔成交后价格可能已变化

    逆向选择：你的单子被吃，往往是因为有知情交易者（信息优势方）在行动

    时间窗口极短：失衡到修复通常只有几秒甚至毫秒级

    对手方是机器人：高频做市机器人会迅速修复定价

    正确做法：单边成交后不补仓，而是：

    如果成交侧盈利 → 挂单退出该侧持仓，或躺平等结算

    如果成交侧亏损 → 立刻止损平仓或跨市场对冲

    五、核心状态机设计

    
    5.1 状态机总览

    机器人只有三种状态，严禁出现第四种状态：

    状态1: Flat(休眠) → 条件满足 → 状态2: MarketMaking(做市) 状态2: MarketMaking → 触发退出条件 → 状态3: ExitOnly(退出) 状态3: ExitOnly → 持仓归零/对冲完成 → 状态1: Flat(休眠)

    
    
    5.2 状态1：Flat（休眠/空仓）

    含义：没有持仓，没有挂单，等待下一个交易窗口。

    进入条件：

    系统启动初始状态

    退出状态完成后

    风控触发后持仓已平

    行为：

    扫描所有5分钟BTC/ETH市场

    筛选符合条件的市场（流动性充足、波动率正常、奖励池活跃）

    等待新周期开始（每个5分钟窗口重置）

    达到挂单条件后切换到 Market Making 状态

    市场筛选条件：

    订单簿深度 > 阈值（确保有对手方）

    当前价差在合理范围内（不过宽不过窄）

    无重大新闻/事件即将发布

    LP奖励池有余额（确保挂单有奖励可赚）

    
    
    5.3 状态2：Market Making（做市）

    含义：在YES和NO两侧同时挂限价买单（Maker），提供流动性。

    进入条件：

    从Flat状态切换

    市场筛选通过

    核心逻辑：

    获取实时订单簿数据（WebSocket）

    计算中间价 Mid Price = (best_bid + best_ask) / 2

    计算库存倾斜（新增重要逻辑）：

    inventory_risk = (YES_position - NO_position) / total_position

    如果 inventory_risk > 0（YES持仓多）：降低YES买入价，提高YES卖出价

    如果 inventory_risk < 0（NO持仓多）：提高NO买入价，降低NO卖出价

    计算挂单价格（考虑库存倾斜后）：

    Buy YES price = Mid Price - spread/2 - inventory_skew

    Sell YES price = Mid Price + spread/2 + inventory_skew

    检查LP奖励区：确保挂单价格在最大激励价差范围内

    检查手续费感知：确保扣除预期费用后仍有利润

    发送Maker限价单到YES和NO两侧

    监控订单状态

    库存倾斜报价逻辑（专业做市商核心）：

    这是之前方案中最薄弱的环节，必须实现：

    5.4 状态3：Exit Only（退出）

    含义：一侧已被成交，停止所有新建单，全力平仓或对冲。

    进入条件：

    Maker单被Taker吃掉（产生单腿持仓）

    风控阈值触发

    核心逻辑：

    如果成交侧为盈利侧（方向对了）：

    选项A: 挂Sell单平仓（锁定利润）—— 挂Sell YES @ 略低于市价（快速成交拿利润）

    选项B: 躺平等结算 —— 不操作，等5分钟结束后自动获得1美元/份

    如果成交侧为亏损侧（方向反了）：

    铁律1: 绝对不允许补仓（买另一边对冲）

    铁律2: 立刻撤销所有待成交挂单

    铁律3: 挂止损单平仓（哪怕亏一点也要出）

    铁律4: 如果仓位较大且Polymarket流动性不足，去Binance开等量反向永续合约对冲

    如果平仓完成 或 对冲完成：

    切换到 Flat 状态

    关键铁律（写死在代码里）：

    铁律1: 有单腿敞口时，只允许退出，不允许新建单边

    铁律2: 绝对禁止补仓操作（逆势加仓）

    铁律3: 止损阈值到达时强制平仓，不允许犹豫

    铁律4: 最后20秒不挂新单（防止操纵/插针）

    铁律5: 单笔最大亏损不超过总资金的2%

    

    
    
    
    六、风控规则（铁律）

    
    6.1 逆向选择防御

    问题：当你的买单被成交时，往往是因为有知情交易者在行动（掌握更多信息或更快），你相当于在和聪明钱对赌。

    防御措施：

    单边成交后不补仓，只平仓

    设置价格异常检测：如果价格在短时间内大幅波动，暂停挂单

    监控成交方向：如果连续多笔被成交的都是同一侧，说明方向可能在跑，暂停策略

    
    
    6.2 库存管理（动态倾斜报价）

    目标：保持Delta中性（YES和NO持仓平衡），通过动态调整挂单价格来主动管理库存风险。

    核心指标：

    inventory_risk = (YES_position_value - NO_position_value) / total_position_value

    分级响应规则：

    风险等级
inventory_risk范围
动作
正常
-0.3 ~ 0.3
正常双边挂单，标准价差
警告
0.3 ~ 0.7 或 -0.7 ~ -0.3
倾斜报价：鼓励成交方向、阻止反向
严重
> 0.7 或 < -0.7
停止该方向挂单，只挂平仓单
紧急
单边持仓 > 总资金5%
强制平仓一半，去Binance开反向对冲
危机
单边持仓 > 总资金10%
全部平仓，切换到Flat状态

    倾斜报价算法：

    # 当 YES 持仓过多时（inventory_risk > 0）：adjusted_buy_yes = mid_price - spread/2 - inventory_risk * skew_multiplier  # 降低买入价（不太会成交）adjusted_sell_yes = mid_price + spread/2 + inventory_risk * skew_multiplier  # 提高卖出价（鼓励别人买）# 当 NO 持仓过多时（inventory_risk < 0）：adjusted_buy_no = mid_price - spread/2 + abs(inventory_risk) * skew_multiplier  # 降低NO买入价adjusted_sell_no = mid_price + spread/2 - abs(inventory_risk) * skew_multiplier  # 提高NO卖出价

    原理：通过调整挂单价格，让市场自然地帮你平衡库存——你不想买的价位挂更高（没人买），你想卖的价位挂更低（容易成交）。

    
    
    6.3 时间过滤器

    问题：5分钟窗口最后几秒存在价格操纵风险（操纵者用大单砸盘/拉盘操控结算价格）。

    规则：

    如果 当前窗口剩余时间 < 20秒: 不挂任何新单，只允许平仓/撤单，等待下一窗口

    如果 检测到异常大额交易（单笔 > 平均10倍）: 暂停该市场挂单30秒，重新评估市场状态

    
    
    6.4 止损纪律

    止损类型
阈值
动作

立即平仓
日止损
当日总亏损 > 总资金的5%
停止交易，等明天

    6.5 手续费防护

    如果 预期利润 < Taker手续费 x 2: 不执行该笔交易

    如果 当前概率接近50%（手续费最高区）: 缩小价差或暂停挂单，等概率偏离后再恢复

    计算示例：

    投入$100，概率0.50，Taker费率1.75% Taker费用 = 100 x 1.75% = $1.75 双边Taker费用 = 1.75x2=3.50 → 价差必须 > $3.50 才有利润空间 → 即价差必须 > 0.035美元

    

    
    
    
    七、执行流程详解

    
    7.1 完整交易循环

    主循环（每100ms执行一次）：

    读取订单簿数据（WebSocket实时流）

    计算中间价、价差、LP奖励区

    计算库存倾斜度 inventory_risk

    检查当前状态：

    Flat → 扫描市场 → 满足条件 → 切换MarketMaking

    MarketMaking → 检查成交/风控/库存 → 可能切换ExitOnly

    ExitOnly → 执行平仓/对冲 → 切换Flat

    更新订单簿（撤旧挂单 → 重新挂单，考虑库存倾斜）

    记录交易日志（价格、持仓、盈亏）

    等待100ms，循环

    
    
    7.2 订单管理流程

    挂单流程：

    计算目标价格（含库存倾斜调整）

    检查LP奖励区（是否在最大激励价差内）

    检查手续费感知（扣除费用后是否有利可图）

    构建订单（包含feeRateBps字段）

    发送Maker限价单

    记录订单ID，启动监控定时器

    撤单流程：

    状态切换时（MarketMaking→ExitOnly）

    价格异常波动时

    风控触发时

    窗口最后20秒时

    重挂流程：

    撤销旧订单

    重新计算价格（基于最新订单簿 + 库存倾斜）

    检查风控条件

    发送新订单

    目标：整个撤单+重挂 < 100ms

    
    
    7.3 跨市场对冲流程（可选高级功能）

    触发条件：

    Polymarket单边持仓 > 阈值

    Polymarket流动性不足，无法及时平仓

    执行步骤：

    获取当前BTC现货价格（Binance API）

    计算对冲数量（与Polymarket持仓等值）

    在Binance开永续空单（方向相反）

    监控两个市场的盈亏

    当Polymarket持仓平仓后，同步平仓Binance持仓

    锁定两个市场的价差收益

    

    
    
    
    八、伪代码框架

    
    8.1 主程序框架

    class MarketMakingBot:    def __init__(self):        self.state = "FLAT"  # FLAT | MARKET_MAKING | EXIT_ONLY        self.position_yes = 0        self.position_no = 0        self.config = load_config()        self.client = PolymarketClient()        self.ws = WebSocket()    def main_loop(self):        while True:            try:                orderbook = self.ws.get_orderbook()                mid_price = self.calculate_mid_price(orderbook)                if self.state == "FLAT":                    self.handle_state_flat(orderbook, mid_price)                elif self.state == "MARKET_MAKING":                    self.handle_state_market_making(orderbook, mid_price)                elif self.state == "EXIT_ONLY":                    self.handle_state_exit_only(orderbook, mid_price)                self.log_state()                time.sleep(0.1)            except Exception as e:                self.handle_error(e)                time.sleep(1)    def handle_state_flat(self, orderbook, mid_price):        # FLAT状态：扫描市场，寻找机会        target_market = self.scan_markets(orderbook)        if target_market and self.is_market_safe(target_market):            if self.is_time_safe():                self.state = "MARKET_MAKING"                self.target_market = target_market                self.place_orders(mid_price)    def handle_state_market_making(self, orderbook, mid_price):        # MARKET_MAKING状态：双边挂单（含库存倾斜）        if self.check_risk_control(orderbook):            self.state = "EXIT_ONLY"            self.execute_exit_strategy()            return        if not self.is_time_safe():            self.cancel_all_orders()            return        if self.has_single_leg_exposure():            self.state = "EXIT_ONLY"            self.execute_exit_strategy()            return        self.refresh_orders(mid_price)    def handle_state_exit_only(self, orderbook, mid_price):        # EXIT_ONLY状态：平仓/对冲        # 铁律：不允许补仓！        self.cancel_all_orders()        if self.can_close_position():            self.close_position()            self.state = "FLAT"        elif self.should_hedge():            self.open_hedge_on_binance()            self.state = "FLAT"        else:            time.sleep(2)    def place_orders(self, mid_price):        # 双边挂Maker单（含库存倾斜调整）        spread = self.calculate_spread()        inventory_skew = self.calculate_inventory_skew()        buy_price = mid_price - spread / 2 - inventory_skew        sell_price = mid_price + spread / 2 + inventory_skew        if not self.is_in_lp_reward_zone(buy_price) or not self.is_in_lp_reward_zone(sell_price):            logger.warning("价格不在LP奖励区内，跳过挂单")            return        if not self.is_profitable_after_fee(buy_price, sell_price):            logger.warning("扣除手续费后无利润，跳过挂单")            return        self.client.place_limit_buy(self.target_market, buy_price)        self.client.place_limit_sell(self.target_market, sell_price)        logger.info(f"挂单: Buy@{buy_price} Sell@{sell_price} skew={inventory_skew}")    def execute_exit_strategy(self):        # 退出策略        if self.is_winning_position():            exit_price = self.get_profitable_exit_price()            self.client.place_limit_sell(exit_price)        else:            stop_loss_price = self.get_stop_loss_price()            self.client.place_limit_sell(stop_loss_price)            if self.position_size > self.config.max_hedge_threshold:                self.open_hedge_on_binance()    def check_risk_control(self, orderbook):        # 风控检查 - 返回True表示需要退出        if self.daily_loss > self.config.max_daily_loss:            logger.critical("日止损触发!")            return True        if self.current_loss > self.config.max_single_loss:            logger.critical("单笔止损触发!")            return True        if self.is_volatility_anomaly(orderbook):            logger.warning("检测到异常波动，暂停挂单")            return True        if self.is_inventory_unbalanced():            logger.warning("库存失衡，准备退出")            return True        return False    def calculate_inventory_skew(self):        # 计算库存倾斜调整量        total = self.position_yes + self.position_no        if total == 0:            return 0        risk = (self.position_yes - self.position_no) / total        # 映射到倾斜量        if abs(risk) > self.config.inventory_critical_threshold:            return self.config.inventory_skew_max * 2  # 极端倾斜，大幅调整        elif abs(risk) > self.config.inventory_warning_threshold:            return self.config.inventory_skew_max  # 警告级别        else:            return risk * self.config.inventory_skew_max  # 线性倾斜

    十、风险提示

    
    10.1 市场风险

    价格操纵风险：5分钟市场存在操纵者用大单砸盘/拉盘操控结算结果的风险，尤其在夜间和周末流动性低时

    流动性风险：极端行情下订单簿可能枯竭，导致无法及时平仓

    结算风险：预言机更新延迟可能导致价格与预期不符

    竞争加剧风险：随着更多机器人进入，价差和返佣可能被摊薄

    
    
    10.2 技术风险

    非原子执行风险：双边订单独立撮合，可能出现一边成交另一边未成交的情况

    系统故障风险：网络中断、程序崩溃、API故障等可能导致无法及时止损

    API变更风险：平台API接口变更可能导致程序失效

    地理封锁风险：Polymarket持续更新受限国家列表，可能影响访问

    
    
    10.3 资金风险

    本金损失：任何交易策略都存在亏损可能，切勿投入无法承受损失的资金

    智能合约风险：底层智能合约可能存在漏洞

    平台风险：平台可能更改规则、暂停提现等

    
    
    10.4 实战数据警示

    根据Pantera Research 2026年上半年数据分析：

    机器人整体虽净赚1.08亿美元，但仅27%的机器人钱包盈利

    中位数机器人仍在亏损

    175万个钱包中仅146个连续6个月正现金流

    零售用户合计亏损约7,400万美元

    这意味着：做市策略不是”装了就能赚钱”的印钞机。你的竞争力取决于：

    代码的稳定性和执行效率

    风控规则的严格程度

    库存管理的精细程度

    你能承受多长时间的亏损期

    
    
    10.5 建议

    先用模拟盘测试：在paper trading环境充分测试后再上实盘

    小资金起步：先用小资金验证策略有效性

    严格止损：永远设置止损，不要心存侥幸

    持续监控：不要完全依赖自动化，定期检查机器人运行状态

    分散风险：不要把所有资金放在一个策略/一个市场上

    关注平台规则变化：LP奖励比例、手续费结构可能随时调整

    11.4 为什么”不赚不赔也能盈利”

    这是做市策略最核心的数学逻辑：

    假设你每天挂单总量为$10,000：

    LP奖励：假设日收益率0.05% → $5/天

    返佣：假设日Taker手续费总量50，你获20%→10/天

    价差收入：假设日均成交2,000，价差0.02→4/天

    逆向选择亏损：假设日亏损$3/天

    日净利润 = 5 + 10 + 4 - 3 = $16/天 月净利润 ≈ $480 即使价差收入为0（不赚差价），你依然每天赚$12（返佣+LP奖励-亏损）

    这就是你关注的那个地址”50%赚差价，50%不赚差价但靠奖励盈利”的数学基础。
