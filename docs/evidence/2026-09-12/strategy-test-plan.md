# 做市策略测试方案

## 目标

在实盘锁定的前提下，验证 5 分钟 BTC 做市策略是否能在可获得的奖励条件下覆盖交易损耗，并明确参与率、收益和风险的关系。测试不把任何奖励假设或零成交结果算作盈利。

## 固定口径

每个市场以完整 CLOB 5 分钟窗口为单位；只使用本机日库；按 UTC 日期划分训练集和留出集；交易费用、退出滑点、未配对仓位和最坏结算分别核算。奖励分三档：零奖励保守档、按官方当期配置估算档、只有链上到账凭证才计入的确认档。

## 阶段一：数据与参考地址账本

1. 检查每个日库 SQLite 完整性、Gamma 元数据、UP/DOWN 两边覆盖和 CLOB 接收时间连续性。
2. 从参考地址 Activity 重建每场成交批次、批量、间隔、首末成交时间和库存差。
3. 把 77 笔已核实返佣/奖励转账按 Taker rebate、Maker rebate、Reward 分类；单独标注它属于参考地址，不属于都柏林账户。
4. 不推断参考地址的未成交挂单、队列位置或真实下单时刻；无法得到真实全市场参与率时，报告为“有成交市场覆盖率”。

## 阶段二：回放器校验

1. 每个参数必须注入 strict、calibrated 和 candidate 三套引擎，并由单元测试断言。
2. 参数组合独立子进程运行，单次只处理有限市场，释放后再运行下一组。
3. 零成交组合标记为无效，不得因为 PnL=0 排名第一。
4. 回放必须输出 simulated fills、paired shares、one-sided markets、最大裸仓、费用、最坏结算和实际结算两套结果。

## 阶段三：策略对照

固定资金上限和订单最小量，比较四类方案：

- 原 strict pair 基线；
- v2 高参与率小批量双边做市；
- v2 加库存 skew、短时流向和尾盘 reduce-only；
- 上述方案在零奖励、估算奖励、确认奖励三种口径下的敏感性。

首腿不要求立即配对，但必须受单场现金上限、最大裸仓金额、最长裸仓时间和单场止损约束。剩余 60 秒停止新首腿，30 秒只允许安全补轻侧或分层退出，10 秒强制撤单。

## 阶段四：选择与验收

训练集只用于选参数；留出集完全不参与选择。候选必须同时满足：零奖励档费用后不出现超预算损失；留出集不是零成交；单边比例和最大裸仓低于基线；估算奖励不能是唯一盈利来源；真实奖励到账仍单独展示。

## 输出

最终报告按策略和日期列出参与率、成交率、价差收益、费用、退出损耗、奖励三档、净收益、最大回撤、单边暴露、资金占用和数据完整性。任何结果不满足数据完整性或参数注入校验，标记为不可用，不进入生产。
