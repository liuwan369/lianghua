# 历史 maker 回测的 tick 数据要求

每条 Up/Down 历史盘口必须提供当时该 token 的真实 `tick_size` 或 `tickSize`，支持数值或数字字符串。两侧 tick 独立读取；发生 tick 变化时，后续盘口应记录新值。

缺失、非有限、非正、超出价格范围或两个别名相互矛盾的 tick 会使 CLI 报错退出。旧的只有 bid/ask 的数据不能直接用于此版 maker 回测，不会自动补成 `0.01`，也不能把缺数据造成的零成交当成策略结果。

历史时间保留已有 `Z` 或 UTC 偏移；未标注时区的旧格式按 UTC 解释。非法时间直接报错，不再回退成 Unix 时间 0。

先按真实 tick 向下量化 maker 委托价，再进行配对成本、费用与份数检查。例：`0.76/0.77` 盘口的插值价格 `0.7615`，在 `0.01` tick 下取 `0.76`，在 `0.001` tick 下取 `0.761`；配对成本上限保持原值。

本要求不改变历史回测的模拟成交与结算推断性质；通过数据校验不代表已经验证真实成交或盈利。2026-09-10 的 paper 单边亏损缺少逐 tick 拒绝日志，不能仅凭此修复认定其唯一原因。
