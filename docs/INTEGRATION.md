# 最小集成方案

## 谁来融合

需要一个专门的集成会话，但它不是重新开发一遍，而是把已完成模块接线并验证。集成会话使用 `codex/integration` 分支，避免多个会话同时改同一个文件。

## 融合顺序

1. 先合并 `shared/contracts` 约定的字段。
2. 合并行情分支，验证市场目录、盘口和场次切换。
3. 合并交易运行分支，验证启动、暂停、停止和订单生命周期。
4. 合并账本/API 分支，验证持仓、结算、统计和日志。
5. 合并前端分支，验证五个页面的 REST/WebSocket 数据映射。
6. 运行一次本地端到端检查，再决定是否部署。

## 快速验收

- 页面打开不报错，导航不回到旧前端。
- 同一 `marketId + roundId` 的行情、订单、持仓能对应起来。
- 行情实时更新不会触发账户、统计和整页刷新。
- 发送相同 `requestId` 不会产生重复命令。
- 断线、过期和接口错误不会把有效数据清空成假零值。
- 账户秘密不经过浏览器。

## 不做的事

不因为集成而增加微服务、消息总线、复杂权限层、历史回测平台或额外审计流程。发现真实问题就修执行链路；没有真实需求的抽象留到以后。
