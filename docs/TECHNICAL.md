# 当前技术实现

更新时间：2026-09-18。本文描述当前本地候选版的实现语义；部署事实以 [CURRENT-STATUS](CURRENT-STATUS.md) 为准。

## 行情热路径

Market WebSocket 是交易判断的实时来源，处理 `book`、`price_change`、`best_bid_ask` 和 `tick_size_change`。同一消息中的 UP/DOWN 更新先批量写入内存盘口，再执行一次策略判断。完整 L2 和买卖一快事件分别维护时序，因此快事件不会让稍后到达的有效 L2 永久失效，同毫秒的价格变化也不会被误判为重复。

决策帧必须有交易所时间戳。盘口清空、连接中断、价格非法、两侧时间偏差或数据超过新鲜度阈值会关闭该市场的新触发。恢复后先重建基线，不根据断线期间的价格轨迹补造阶段或订单。

REST 不参与逐次触发。它只用于市场发现、tick/元数据、启动与重连恢复、未知订单查回和后台账户核对。User WebSocket 直接驱动订单与成交更新。

## 反转状态机

每个五分钟场有独立状态：配置版本、基线、触发方向、待确认冲突、已消费阶段、订单和结束状态。初始样本位于触发区间或某一侧从下方跨过 `triggerPrice` 时，按 `stageShares` 推进一个阶段，并以 `maxBuyPrice` 作为买入限价。后续阶段必须与上一阶段方向相反。

`confirmationPrice` 用于记录方向已经达到确认区和统计反转次数，不会增加固定等待或延迟下单。策略响应每一批新的有效盘口，而不是按确认次数轮询。

双边在同一批次同时满足条件时进入 `pendingAmbiguity`，等待后续有效价格明确方向。同方向重复帧不重复消费阶段。重启恢复已经持久化的阶段和订单；新配置只用于尚未开始的新场。自动发现当前和下一场，旧场仍保留未决订单、迟到成交和结算处理。

## 订单与并发

订单状态包含提交中、开放、部分成交、全部成交、取消、拒绝和未知。BUY 预留名义金额及费用，SELL 预留份额。明确拒单释放预留前必须保存终态；提交响应丢失则保留签名身份和预留，先按原身份查回。

同一 `clientOrderId` 的提交、查回、撤单和重试串行并去重。不同订单可以同时签名后发送 HTTP；全局短锁只保护状态检查、预留和提交身份的耐久写入，不覆盖网络 ACK 等待。取得锁后重新检查停止/风险状态、单场与总预算、开放订单数、可用现金、可卖份额和费用余额。

成交用 `tradeId + orderId` 去重。撤单 ACK 与在途成交可以竞态，`CANCELLED` 本身不证明没有迟到成交；需要核对的余量保持 `reconciliationPending`。成交状态的终态不能被旧消息倒退。

## 资金、费用和收益

新增订单同时受真实可用现金、工作单占用、市场最小份额、单场预算、可选总预算和可选日内亏损停止线约束。历史 `$50/$30` 不是固定限制。费用优先使用交易所报告；费率推算或估算明确标记来源，不计入“已核实费用”。

日内结果以交易现金账本为边界。确认的 pUSD/USDC.e 资金流在后台扫描，用于区分充值、提现、转换和交易结果。资金流覆盖落后时页面显示暂估，扫描不进入行情、签名、提交或 ACK 热路径。

## 持久化与恢复

`PlatformStore` 使用账户隔离锁、临时文件、`fsync` 和原子替换。发单前关键状态一次提交；普通遥测和后台投影异步追加。当前仍有一项性能改进：把完整状态快照进一步收敛为最小追加 WAL 事务，但不得牺牲未知提交身份和资金占用恢复。

启动或重连时先读取真实开放订单和成交，再接纳账户余额/持仓快照。恢复失败、User WebSocket 不连续或目标市场盘口不健康时停止新单。停止命令处理本系统工作单后退出；进程退出不等于远端订单已经确认取消。

## 结算

标准 CTF 市场读取链上结算向量、真实持仓和 pUSD 余额后赎回。结算请求在发送前保存已签身份；响应丢失时只重放同一请求。只有成功回执、对应资产转移和持仓清零都成立，才标记 `confirmed` 和真实到账。EOA 与已支持的 Deposit Wallet 走现有 sender；无法识别的钱包或资产路径返回明确不支持。

## 延迟口径

平台分别记录：

- `market_age`：交易所事件到本机接收时的数据年龄，可能受机器时钟误差影响。
- `book_processing` / `book_batch_apply`：盘口解析与同批次应用。
- `strategy_decision` / `ws_receive_to_decision`：本机接收至策略决策。
- `durable_commit`：发单前关键状态写盘。
- `order_sign`：订单签名。
- `trigger_to_http_post` / `decision_to_http_post`：行情或决策到 HTTP 发出。
- `order_submit_roundtrip` / `order_http_ack`：CLOB 提交往返和 ACK。
- `authenticated_trade_report`：认证用户频道的成交回报。
- `cancel_http_ack`：撤单请求到交易所确认。
- `reaction`：完整反应链路的聚合视图。

控制台展示 latest、p50、p95、p99、max 和样本数。没有当前运行样本或超过 15 秒时显示未知。等待对手方成交不属于代码反应延迟。

## 服务器指标

后台提供 CPU、内存、磁盘、系统负载和关键进程 PID/RSS/uptime。进程身份同时核对 PID 和启动信息，避免 PID 复用显示成健康交易进程。指标用于发现资源争用，不参与行情决策或下单门禁。
