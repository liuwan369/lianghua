# 技术实现与执行语义

更新：2026-09-17。版本 `a9d37cd` 已部署，主要代码 hash 已匹配；本轮真实订单尚未执行。主实现位于 `_external/btc-5m-market-trading-bot/src/platform/`、`src/strategies/btc-reversal.ts`、`src/cli/platform.ts`，控制台使用 `scripts/dashboard/strategy_config.py` 和 `web/src/pages/`。

## 模块与启动

`TradingPlatform` 提供 market/account/orders/portfolio/risk/history/settlement/telemetry 八类能力。`BtcReversalStrategy` 只接收平台事件、输出交易意图；不直接调用交易所、不改写账户账本。

控制台通过 `/api/strategy-config` 保存版本，通过 `/api/trading/control` 启停、暂停或恢复。运行使用 `--live --strategy btc-reversal --strategy-config <path>`，服务器检查配置版本、唯一请求编号、账户与实盘开关。

每次运行生成独立 journal、console、stop/control 文件。**账户对应的 `btc-reversal-<identity>.platform-state.json` 跨运行复用**，包含账本、订单及策略阶段；赎回状态使用旁路 `.settlements.json`。不能每次启动清空持仓或重新创建第一阶段。

未指定固定市场列表的反转运行每 15 秒发现当前及下一场市场。运行时长 0 表示持续运行，不因当前五分钟场截止而退出；旧场继续管理未决订单、持仓和结算。

## 策略与参数

参数包括触发价、确认价、最高买价、阶段份额、阶段数、单场/总预算和可选日内停止线。价格、阶段和预算的新版本只用于尚未开始的新场；当前场保留创建时版本，运行时长在下一次启动生效。

跨价触发和反转确认分别记录。同方向反复跨价不新增阶段；对侧触发时不等待旧单全部成交，也不撤销旧方向的工作单。订单使用非 post-only 的 GTC 买入限价，最高买价固定，余量继续挂单，成交价格以自己的真实回报为准。场次结束处理余单，继续接收迟到成交。

中途冷启动等待下一场；重启恢复已有阶段和订单。行情重连重建价格参考，不补造断线期间阶段。两个历史参考模板仍是一套可编辑逻辑。

## 订单、费用和资金

订单状态覆盖提交中、开放、部分/全部成交、撤销、拒绝和未知。BUY 预留金额及费用，SELL 预留份额；有效工作单和未知请求不能重复使用同一资金。

成交按 `tradeId + orderId` 去重，同时处理 MATCHED、MINED、CONFIRMED、FAILED 等状态变化。失败可冲正对应暂记变化；重复或迟到旧事件不能重复扣款或推翻终态。费用区分交易所报告、费率推算和估算，预留费用不冒充实际费用。

撤单确认可能与迟到成交竞态，`reconciliationPending` 保留需要核对的余量。恢复时先补真实订单和成交，再接纳账户快照；账户核对通过后才更新账本。策略预算与实际可用余额共同限制新增，不使用固定历史资金额度。

日内结果以 pUSD 交易现金为账本边界。后台每30秒增量扫描 Polygon 已确认的 pUSD/USDC.e Transfer 日志，并用成功回执、协议对手方或账户活动类型归因；pUSD onramp 流入记充值、offramp 流出记提现，USDC.e 转换腿只作证据，不重复计入。游标、已应用资金流和日内基线与账户账本同一持久提交，重启不重复调整。扫描与订单恢复并行隔离，不进入下单、ACK或撤单路径。

链上确认覆盖可能落后于最新现金读取。此时 `cashFlowComplete` 表示已扫描窗口是否完整，`pnlVerified` 表示该覆盖是否追上现金观察时间；页面把日内结果标为暂估。覆盖不全本身不设交易门槛，用户配置的日内停止线仍按当前暂估结果执行，后续确认的充值提现会修正基线。

## 行情与延迟

盘口保留完整买卖深度，买价降序、卖价升序，价格精度按市场 tick。新单仅检查**目标市场**双边行情和认证用户频道，过期旧场不能阻止新场交易。断线暂停新触发，重连获取完整盘口并补订单/成交。

热路径为行情事件、本地策略判断、资金预留、签名提交；不把远程余额、持仓、成交及订单查询串在每次触发前。用户频道成交直接更新平台，REST 用于恢复和核对。

控制台已实现多档盘口、行情数据年龄和分段延迟显示；无有效来源显示 `--`。行情处理、策略判断、签名、订单 ACK、撤单 ACK 和成交回报分别计量，不把等待对手方成交的时间当代码延迟。跨机器消息时间差可能含时钟误差，实际端到端样本仍待本轮真实验证。

## 持久化与结算

`PlatformStore` 使用独占锁、恢复快照和原子替换保存账户与策略状态。结算 sender 在提交前持久化已签请求；响应丢失或重启后先查原请求，只重播同一签名、nonce 和 deadline，避免重建经济请求。

标准 CTF 市场先读取官方链上结算向量、实际持仓及 pUSD 余额，通过 pUSD collateral adapter 赎回。当前 sender 支持 EOA/Deposit Wallet；neg-risk、Safe/proxy 或无法识别的资产路径返回具体 `unsupported`，不伪造成功。

赎回只有 receipt 成功、对应 pUSD 转账和持仓清零核对后才返回 `confirmed`，平台随后重新读账户，不手动再加一遍余额。若本就无持仓则明确“无需赎回”，不记录虚构收入。退出交易进程后状态保留，后续恢复运行继续处理；不承诺已停止进程仍执行后台赎回。
