# 动态补仓模型与研究边界

基础模型说明来自 2026-09-10；补腿政策于 2026-09-13 重新核对。当前研究目标以 [交付规划 v2](STRATEGY-DELIVERY-PLAN-2026-09-13.md) 为准，最新外部来源见 [本轮调研](research/autonomous-market-making-sources-2026-09-13.md)。

## 当前实现

TypeScript 引擎的 `strategy.ts`、`inventory.ts`、`risk.ts` 与 `models.ts` 实现库存平均成本、预计配对成本、动态补腿份数、失衡/预算/最坏亏损约束以及公开盘口下的 maker 成交概率估算。实际入口配置为 `targetClone()`；其他研究预设不能冒充当前运行配置。

maker 价格先按每个 token 的真实 tick 向下量化，再进入成本、费用、数量和执行校验。缺少真实 tick 则拒绝。有效挂单、待撤、部分成交剩余量和未终态吃单保留资金及风险占用；最低份数不足时不扩大订单。

## 动态份数模型

设较重侧 A 的数量/成本为 qA/CA，待补侧 B 为 qB/CB，A 平均成本 aA=CA/qA，预计 B 单份全成本为 pB，目标配对成本为 T，允许 B 均价 H=T-aA。

```text
pair_after(x) = aA + (CB + x*pB) / (qB + x)
x_min = (CB - H*qB) / (H - pB)
```

第二式只在需要压低 B 均价且 pB<H 等适用条件下成立，不能无条件套用。实际份数还同时受可用资金、费用、未配对库存、失衡、最坏损失、市场最小份数和盘口约束；裁剪后重新核对预计配对成本。pB 不足以改善目标时应拒绝或等待，不能为凑对冲无条件追价。

`target_clone` 启用 `dynamicHedgeSizing`。当前 `hedgeLimit()` 从基础 `hedgePairCostCeiling=0.99` 出发，按裸仓时间/尾盘阶段调整到配置的应急门槛，候选和最终份数计算使用同一结果；资金、最坏损失和最小份数仍可阻止提交。旧的“候选放宽但最终始终 0.99”说明已失效；实际成交与退出效果需另行验证。

## 成交概率和收益

`estimateMakerFillProbability` 使用公开队列量、近期成交速度、订单份数、寿命、价距与波动估算概率；它不是平台提供的本人真实排队位置。真实 maker 成交概率、撤单重挂后的队列损失和不利选择仍需账户成交校准。

研究动作评分可比较配对边际、未对冲最坏损失、不利选择、gas/运营成本及已确认奖励。实际奖励没有逐笔凭证时不能作为确定收入；历史回测默认不靠奖励填补亏损。手续费必须统一是否已经包含，避免重复扣减。
