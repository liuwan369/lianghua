# 自动做市系统交付规划

日期：2026-09-16
版本：v7
状态：**底座审查进行中，策略暂停**

当前事实以 [当前系统状态](CURRENT-STATUS.md)、源码、测试结果和带日期证据为准。本文是交付顺序和协作规则，不把接口存在、服务在线或 paper 盈亏写成自动实盘完成。

## 1. 交付目标

先交付一套可被任何策略调用的交易平台，再单独接入策略。平台负责行情、账户、订单、持仓、资金预留、风险、结算、持久化、延迟和控制台数据；策略只负责根据事件产生交易意图。这样后续更换做市、方向、套利或观察策略时，不需要重写交易底座。

系统目标分成两条线：

- **平台线**：接口契约、订单生命周期、资金账本、恢复、延迟和展示正确。
- **策略线**：独立研究、回放、paper、真实校准、参数和收益。当前策略线暂停。

## 2. 当前状态

已完成：公共 `TradingPlatform`、`TradingCore`、`StrategyPlugin`、独立 `PaperGateway`、Polymarket 适配器、深度行情字段、持久化锁和通用 CLI。BUY/SELL、多订单、部分成交、撤单、替换和重复成交去重已有模拟回归。

控制台新启动、停止、进程身份恢复和状态/日志投影已迁入公共平台，默认无策略观察。只应用 mode/duration，其他七项旧配置保留；模拟余额与真实账户分开显示，过期数据不当作当前状态。旧 CLI 仅作显式兼容入口。

未完成：真实部分成交和撤改竞态、断线中成交、异常恢复、长期连续运行、账户资金联合核对、结算到账对账、控制台五档深度及完整分段延迟展示。平台观察目前在所选市场全部到期后停止，自动换场待补。

当前服务器交易停止，`mode=paper`，`live_unlocked=false`。旧策略和证据保留为历史/兼容用途；不再把 `stableLive`、`target_clone`、`pair-cost` 或旧 paper PnL 当作当前生产策略。

## 3. 阶段顺序

```text
P0 事实基线与文档统一
  -> P1 公共平台契约审查
  -> P2 订单、资金、恢复和适配器验收
  -> P3 控制台展示和运维核对
  -> P4 策略接口验收（暂停）
  -> P5 策略研究、paper 和真实校准（暂停）
  -> P6 受限自动运行（暂停）
```

### P0：事实基线与文档统一（完成，持续维护）

以当前源码和测试为唯一实现来源，清理“策略已完成”“自动实盘已完成”“原子账户是唯一阻塞”等失效表述。历史报告保留，但必须带日期并注明历史性质。任务树必须把公共底座、策略接口、真实验证和网页展示分开。

通过条件：当前文档相互一致，任务树可以由页面读取，策略状态统一为暂停，服务器不被文档整理改变运行模式。

### P1：公共平台契约审查（当前）

审查 `src/platform` 和旧 live 适配器之间的契约：订单状态迁移、BUY/SELL 预留、部分成交、迟到成交、撤改单、重复事件、策略权限、深度排序、错误传播、持久化和关闭顺序。发现问题先补测试和修复，再更新文档。

通过条件：公共测试、类型检查、构建和针对性故障用例通过；没有未记录的状态或资金守恒问题。

### P2：真实执行和账户核对（暂停策略但继续底座工作）

在不运行自动策略的前提下，完善真实适配器的生命周期证据：真实 ACK、撤单、部分成交、替换竞态、断线重连、迟到回报、退出后空单和账户余额/持仓核对。慢 REST 读模型不能进入成交驱动热路径。

通过条件：每笔测试订单都有最终状态，未知订单不会释放预留；重启、异常和关闭后能恢复或明确停机；未核实的资金不显示为零。

### P3：展示与运维

已迁移控制台的启动、停止、进程身份恢复和状态/日志投影，默认启动不挂策略的公共平台；旧 CLI 的兼容入口明确保留。当前补五档页面、分段延迟、自动换场与持续稳定性；这些可以与 P2 的只读核对并行推进，不等待策略恢复。systemd 服务重启会终止同组子进程，不宣称已完成重启自动续跑。

保留现有六页前端，只补真实缺口：五档/完整深度、订单生命周期各阶段时间、来源和消息年龄、自动调整原因、数据过期状态、账户数据范围。页面不能用示例数字填充在线状态。服务器发布采用本地、Git、服务器三段核对并保留回退。

通过条件：页面状态与接口一致，离线时清空旧行情并显示原因；发布清单、服务状态、构建哈希和回退包可核验。

### P4-P6：策略线（暂缓）

策略线只在 P1-P3 通过后恢复。恢复顺序为：

1. 以 `StrategyPlugin` 编写一个只读观察插件，确认事件和只读上下文隔离。
2. 用固定数据做回放和 paper，记录成交假设、费用、库存、退出和风险。
3. 用独立小额探针校准 ACK、成交、队列、部分成交和退出，不把删失样本填成成交。
4. 只有平台闭环和策略证据均通过，才讨论默认参数和受限自动运行。

在策略恢复前，不接入旧 `PairCost` 规则，不根据历史 PnL 调参，不启动完整自动实盘。

## 4. 硬边界

- 本金上限 `$50`，北京时间单日最大损失 `$30`；盈利不自动提高额度。
- 默认 paper；真实网关只能由显式 `--live` 和独立解锁共同启用。
- 未知订单、失效行情、持久化失败、账户核对失败和停止后残单都会停机。
- 任何策略不得直接导入 CLOB client、修改资金账本或绕过风险接口。
- 复杂审计和 provider 原子快照不是当前唯一阻塞，但也不能把普通分段读取伪装成原子数据。

## 5. 交付与回退

每批只包含一个明确范围：记录基线，冻结 diff，运行测试/类型检查/构建，进行代码复核，提交并推送，生成发布清单，备份服务器替换文件，部署，核对源码和服务，最后更新文档。失败时只回退本批文件，保留订单、账本和风险状态；不覆盖用户未提交的研究改动。

## 6. 当前完成判定

控制台：**PARTIAL**。六页和任务树可用，五档深度及完整延迟展示未完成。
