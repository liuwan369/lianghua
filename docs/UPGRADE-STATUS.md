## 已完成

- 都柏林服务器持续采集真实公开数据：Polymarket 盘口、公开成交、BTC 行情和 Polygon 链上成交日志；东京数据保留作历史对照。

- 修复实盘部分成交的订单跟踪；未成交的剩余部分不会丢失，停止时可以继续撤掉。
- 修复模拟页面重复统计吃单，并修复停止行情后仍延迟运行的问题。

- 只读账户核对已完成：API/公开地址 `0xA693a0E0e40BDeC3d9d4a40bD4D087A5cECFD7cd`，现金/组合约约 `$17.13`，无持仓；Relayer 签名地址 `0xDa6F73818Af63191633D8c8025508CD703780CD0`，暂无 Relayer API 密钥。
- 没有官方结算价时不会猜输赢，页面保持“未结算”。
- 交易热路径已完成第二轮加固：主盘口和用户成交 WebSocket 是实盘硬门槛；盘口超过 `250ms` 禁止下单；任一频道掉线立即撤单停止；下单本地签名后直接 POST，3 秒超时；成交先于 ACK 时短暂缓存；ACK 成交编号后台核对；任何订单状态不明确都停止而不是重复下单。
- WebSocket 完整盘口建立后，旧时间戳增量会被丢弃，防止乱序消息把本地订单簿倒退。
- ACK 状态未知时保持用户回报通道在线，撤单后至少观察 5 秒，读取稳定的本市场完整账户成交并重建仓位，连续确认无残留挂单后仍停止运行，不自动继续真钱交易。
- maker/taker 成交统一按成交事件记账，订单状态更新不再重复计仓；无用的逐交易所明细不会进入策略队列。
- 已移除安全公告确认的恶意依赖 `poly-price-node@1.1.2`，改用官方 CLOB 健康检查。当前仍跟踪官方 SDK 内部旧版 `ws` 的传递性高危告警，不在未验证兼容性的情况下强制降级 SDK。

- 统一测速器已支持跨 5 分钟市场自动续测、WebSocket 心跳、末尾静默统计和时钟偏差校准门槛；修正后的东京复核报告为 `data/latency-tokyo-smoke-final.json`，结论仍是不合格。
- 官方地理文档已核实：主服务器在 `eu-west-2`，普通开发者最近区域是 AWS 都柏林 `eu-west-1`；都柏林已成为当前主节点。
- 都柏林 30 分钟统一基线为 REST `p50=26.19ms / p95=35.38ms`、稳定盘口消息年龄 `p50=9ms / p95=86ms`，明显优于东京。当前仍未配置私钥，不会下真钱。

## 现在能看到什么

- 当前 Up/Down 买一、卖一和两边卖价合计；
- 模拟挂单、撤单、真实盘口触发的纸面成交；
- 成交份数、成交金额、手续费和结算后的模拟盈亏；
- 运行参数和每个市场汇总。

如果两边卖价合计高于配置上限，例如 `$1.01 > $0.99`，系统会明确不下单，这是策略条件不满足，不是页面故障。

## 还没有完成

- 都柏林只读网络基线和内核短时 A/B 已完成；16MB 缓冲区候选仍需长测，不能把公开测速冒充真实下单延迟。
- 公共数据看不到目标订单在队列中的精确位置，因此历史回放不能证明一定能成交。
- 挂单撤单的完整私有参数、平台返佣和流动性奖励，公开数据无法逐笔还原。
- 成交概率目前作为模型基础和回测参数，尚未用来冒充真实成交；需要用都柏林连续数据和极小额真实订单校准。
- 纸面撮合仍是“公开成交打到价格后才成交”的保守回放，不知道真实账户排队序号，不能当作保证成交。
- 真实账户的订单回报、手续费、返佣和奖励对账尚未接入。
- 都柏林当前未配置账户签名、未解锁实盘、未创建真实订单；原因是账户和真实订单链路尚未验收。
- 该分析窗口存在历史采集断点（WebSocket 重连、队列曾满、Binance 序列缺口），报告的完整性门槛为未通过；这表示分析结果可用但不是无缺口全量数据。

## 口径

公开数据是真实市场数据；纸面成交是模型结果；返佣、奖励没有证据时按 `$0` 计算。任何模拟盈利都不能当作已实现收益。
