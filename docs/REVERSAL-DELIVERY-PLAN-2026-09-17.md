# BTC 五分钟反转交易系统开发规划

日期：2026-09-17。版本：v1。当前交付为旧系统备份、技术评估、开发分工和任务树；新策略及页面尚未实现。

本文件替代原自动做市交付规划。停止做市方向，复用交易底座，实现桌面方案的真实交易。目标一个集中工作日完成开发联调；不增加回测、连续 paper、第三日期、午夜基线或数日观察这些等待条件。

## 1. 交付目标

交付可保存配置、启动真实策略、连续切换 BTC 五分钟场次、管理订单持仓、恢复中断、取得官方结果并自动赎回到账的系统。普通用户只选择70/75方案、资金边界和运行方式。

公共行情、BUY/SELL、撤单、账户和结算能力继续复用；做市策略退出产品入口和默认启动链路，前端删除做市专属内容。旧系统先备份，执行阶段按依赖删除不用的做市专属入口，历史账单保留。

结论：**能接入，但还缺策略恢复、连续换场、未知订单查回、真实费用及自动到账闭环。** 不能只换名称就称为上线。规则来源及详细风险见 [技术评估](REVERSAL-TECHNICAL-ASSESSMENT-2026-09-17.md)。

## 2. 统一策略规则

| 参数 | 70方案 | 75方案 |
| --- | --- | --- |
| 卖一跨价触发 | 低于67到不低于67美分 | 低于70到不低于70美分 |
| 反转确认价 | 70美分 | 75美分 |
| 最高买价 | 70美分 | 75美分 |
| 四阶段新增份额 | 5、18、54、130 | 5、22、75、236 |
| 实盘选择 | 两种方案二选一，同账户互斥 | 两种方案二选一，同账户互斥 |

1. 第一阶段接受任一方向有效跨价；之后只有相反方向的新跨价才创建下一阶段。同方向反复跨价不加阶段，采用原文06的明确规则，消除09歧义。
2. 触发、阶段订单、确认反转、实际成交分别计数；不等待旧单成交或确认价才下下一阶段。最多四阶段。
3. 使用 `BUY GTC, postOnly=false`，首次可立即成交，余量继续挂单。反转不撤旧方向单、不提高最高价、不把部分成交重新整笔提交。
4. 只认交易所真实成交。首次提交可能得到更低价；已挂在70美分的买单不能用后来60美分卖一当自己的成交价。这是原纸面成交假设必须修正之处。
5. 不增加最后20/10秒禁止下单。实际截止停止新增、撤余量、继续处理迟到回报，之后按官方结果结算。
6. 报价年龄不超过2秒、双边源时间差不超过1.5秒；无可信盘口只暂停新触发，不擅自撤正常旧单。重连重建跨价参考，不补造丢失期间的阶段。
7. 首次无状态启动等下一场完整起点，最多一个五分钟场次；已有状态则恢复当前场。首条高价样本不伪造成跨价。
8. 参数保存到服务端，方案和份额变更默认下一场生效；当前订单按原版本继续管理。网页关闭不影响执行。

## 3. 底座复用与缺口

`engine/` 指 `_external/btc-5m-market-trading-bot/`。

| 模块 | 已有能力 | 本次实现及完成判据 |
| --- | --- | --- |
| 策略 | `StrategyPlugin`、只读上下文、订单意图 | 新 `btc-reversal` 插件、配置/阶段持久化；重启不重新下第1笔 |
| 行情市场 | 规则、token、完整L2、用户WS | 预热下一场并自动换场；旧场订单与结算继续跟踪，不串token |
| 真实订单 | SDK签名、提交/撤单、部分成交 | 保存签名订单身份、未知ACK查原单、离线成交补齐；不重复经济订单 |
| 成交账本 | 预留、去重、持仓存储 | MATCHED后FAILED冲正、按市场token对账；不重复扣退资金 |
| 费用资金 | 余额/持仓读取、费用预留 | 当前市场费率、真实扣费资产、预留与真实费用分开；现金持仓相符 |
| 官方结算 | 结果/赎回接口、calldata编码 | 接钱包或relayer sender、回执及实际到账；广播不算完成 |
| 运行API | 启停、状态和日志投影 | 策略注册、配置版本、真实启停、场次、统一订单分页 |
| 前端 | 六入口、账户和遥测组件 | 去做市、反转状态、普通配置、订单10/20/50分页 |

已核实的代码问题：旧场健康会阻挡新场下单；单场重连查询错误比对全账户订单；FAILED被忽略；CLI未接真实赎回sender；成交费仍固定估算。具体函数与修改口径见技术评估6.1。这些是待修代码，不是等待更多天数据。

官方文档核验新增要求：部分涨跌市场 `itode=true` 有250ms主动成交等待，必须记录该市场标记，不能把全部ACK耗时归因代码；GTD有最短有效时长约束，首版采用GTC加截止撤单；MATCHED不是最终链上确认。官方链接及核验日期见技术评估第10节。

## 4. 接口与速度

以下是待实现的能力契约，复用现有API风格，不另造框架。

| 能力 | 必要字段或行为 |
| --- | --- |
| 策略配置 | strategyId、scheme、字段定义、savedRevision、activeRevision、nextRoundRevision |
| 启停 | 策略/配置版本/模式；返回真实实例与进程。暂停新增和停止撤余量分开，均继续跟踪持仓结算 |
| 场次状态 | conditionId、tokens、start/end、阶段1–4、触发方向、确认方向、订单归属、持仓、原因、版本 |
| 订单列表 | 实例/场次/状态筛选、limit=10/20/50、游标；真实orderId一单一行，fills展开 |
| 场次收益 | 官方结果、实际成本/费用/持仓、应得返还、赎回状态/txId、实际到账、净结果 |
| 实时推送 | WS或SSE序号/行情/订单更新；断流补快照。浏览器轮询不参与交易决策 |

热路径：`行情事件 -> 本地跨价与阶段判断 -> 持久化意图/预留 -> 签名提交`。用户回报即时更新账本，全量账户、历史查询、页面刷新放后台；重启或未知提交才做针对性恢复，不能每笔先串行远程查四遍账户。

业务唯一键为 `instance + conditionId + stage`。本地clientOrderId不等于官方查询键；保存已签payload/hash和返回orderId，超时先查同一单。一次404或开放订单列表缺失不能证明原单未成交。

分别展示消息年龄、本地计算、持久化、签名、HTTP ACK和认证回报。本地事件处理目标p95在20ms内，磁盘与网络单独实测；不承诺交易所毫秒ACK，也不把等待对手方成交算作代码处理延迟。

```text

自动交易：策略方案、启停、场次倒计时、UP/DOWN卖一
          展开5/10档深度、消息年龄、四阶段进度、确认反转数
          下一笔方向/份额、真实持仓、两种赢家下预计结果
          订单筛选 + 每页10/20/50 + 上一页/下一页

      70/75方案选择
      策略参数 | 运行设置（二级标签，只展示当前标签）
收益：按场次显示成本、费用、官方结果、赎回及到账
设置：账户接入、系统诊断
```

删除配对成本、库存偏斜、双边报价、补仓等待、尾盘补齐、逆向撤单、做市奖励宣传和JSON草稿编辑器。已到账历史奖励可保留为普通收益记录。

订单一行一单，不把每次部分成交和撤单混排成多个订单。默认当前场、可选全部场；历史页实时刷新不跳页；无完整计数不造总页数。市场显示BTC及起止时间，完整ID放详情。页面不展示开发说明。

## 6. Agent分工

最多同时四个Agent，包括主Agent。接口先定，三条实现线并行；共享文件只有一名修改人。

| 角色 | 独占文件范围 | 交付 |
| --- | --- | --- |
| 主Agent/集成 | `scripts/dashboard/`、当前文档/任务树、发布清单 | API契约、配置和投影、合并、真实联调、发布/回退 |
| 策略Agent | `engine/src/strategies/btc-reversal*`及测试 | 70/75状态机、意图、恢复状态、策略配置定义 |
| 执行Agent | `engine/src/platform/`、`src/live/`、`src/cli/platform.ts`及测试 | 核心类型、订单身份、换场、费用、恢复、自动赎回 |
| 前端Agent | `web/src/`及测试 | 普通配置、反转执行、统一分页、启停接线 |
| 独立复核Agent | 实现完成后接替空闲槽位，只读复核 | 找状态/资金/恢复及UI问题，交原负责人修复 |

本轮评估由 `strategy_spec`、`platform_integration`、`frontend_reversal_plan` 完成；评估不等于代码完成。共享接口由主Agent确定，engine类型由执行Agent修改。任何人都不覆盖其他人的未提交研究文件。

## 7. 一个工作日的顺序

这是集中工作的目标预算，不是交易所结算时间保证；并行时间不相加。

| 阶段 | 目标时间 | 工作及结果 |
| --- | --- | --- |
| R0备份与规划 | 本轮收尾 | 本地/服务器快照、输入副本、规则/代码/前端评估及开发规划 |
| R1策略与底座 | 第0–4小时 | 策略、执行并行；主Agent接API；可加载插件、存配置、换场恢复 |
| R2页面接线 | 第1–5小时 | 前端按契约开发；去做市页面、分页、真实启停和状态 |
| R3短时验证 | 第4–8小时 | 独立复核、故障测试、线上小额真实订单；缺陷当场修复 |
| R4发布运行 | 第8–12小时 | 本地/Git/服务器同步；核对完整策略启动条件并运行 |

不以“观察几天”作排期。官方未结算显示待到账，继续其他开发。满四次反转或罕见失败等软件分支用短时故障用例覆盖，不靠等市场；线上未出现的样本如实标注。

## 8. 必须完成的验证

1. 跨价只触发一次、同向不加阶段、对向可独立创建、最多四笔、尾盘无自创禁入规则。
2. 部分成交仅管理余量，反转不撤旧单；旧单和新单并存，真实费用不按盘口猜。
3. 超时、ACK前成交、重复/迟到/FAILED回报、断线中成交及重启，均不重复下单/扣款。
4. 换场不串token/版本，旧场过期不拦新单，旧场占用与待到账不重复使用。
5. 小额真实订单完成ACK、至少一笔实际成交、独立挂单撤销、认证回报、重启查回及账户核对。不使用自己账户对敲制造成交。
6. 至少一笔赢家持仓走官方结果到实际赎回到账；可用已有合适持仓验证。没有到账回执就保留未通过状态。
7. 配置刷新不丢、分页不重不漏、真实停止有效；桌面/手机截图确认内容不溢出。

短时自动化测试检查软件行为，不是策略回测或模拟观察。运行受影响测试、类型检查及构建；跨模块再跑集成回归。不用既有60项底座测试通过冒充新策略验收。

## 9. 资金配置

原版70四阶段名义买入 **144.90美元**，75为 **253.50美元**。桌面参考费用下约 **147.94/257.94美元**；当前代码最大费预留约 **148.52/259.42美元**。多场未结算及实际网络费用可能增加占用。

此前明确的实盘上限是本金 **50美元**、日损 **30美元**。桌面300美元是纸面本金，不能自动变成新的实盘额度。旧额度可做最小真实接口验证，无法跑完原版四阶段。工程可以继续，完整原版启动依赖资金配置落地；不暗改份额凑额度、不把最小订单测试说成完整策略上线。

按参考费率与满成交假设，第1/3阶段方向最终获胜时，70约亏 **88.94美元**、75约亏 **177.94美元**；另一方向约余 **0.057/0.064美元**。日损停止新增无法消除已有持仓风险。页面显示资金占用及两种赢家结果，不把“可能保本”当作损失保证。

日内损失使用可追溯真实权益、出入金和交易活动，能恢复当日则恢复；不能恢复的范围明确显示，不造午夜数据。额度统一服务端，不能只改前端或漏掉第二处硬编码。不等待午夜才做开发或接口验证。

## 10. 当前状态与回退
