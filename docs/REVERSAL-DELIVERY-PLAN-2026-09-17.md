# BTC 五分钟反转交易系统开发规划

日期：2026-09-18。版本：v1.7。反转策略、底座、API、前端、撤单 ACK 遥测、到账投影和预算提示已在软件发布基线 `70d2b55` 部署并通过公网验收。服务器保存配置为 revision 3，尚未启动真实策略，最新事实见 [CURRENT-STATUS](CURRENT-STATUS.md)。

本文件替代原自动做市交付规划。停止做市方向，复用交易底座，实现桌面方案的真实交易。目标一个集中工作日完成开发联调；不增加回测、连续 paper、第三日期、午夜基线或数日观察这些等待条件。

## 1. 交付目标

交付一个可保存参数、启动真实策略、连续切换 BTC 五分钟场次、管理订单持仓、恢复中断、取得官方结果并自动赎回到账的系统。普通用户配置触发价、确认价、最高买价、阶段份额、单场/总预算和运行方式；70/75 只是已观察过的参数模板，不是两个策略或固定方案。

公共行情、BUY/SELL、撤单、账户和结算能力继续复用；做市策略退出产品入口和默认启动链路，前端删除做市专属内容。旧系统先备份，执行阶段按依赖删除不用的做市专属入口，历史账单保留。

结论：**已经接入底座，策略恢复、连续换场、未知订单查回、费用、结算适配和外部资金流修正均已实现。** 当前交付按三个真实闭环推进：真实费用/收益/到账核对，最小真实 ACK/成交/撤单/重启恢复，正式参数运行/自动换场/结算到账。真实订单和资金操作由用户发起；没有真实证据的项目保留未完成。规则来源及详细风险见 [技术评估](REVERSAL-TECHNICAL-ASSESSMENT-2026-09-17.md)。

## 2. 统一策略规则

| 参数模板（可编辑） | 70参考模板 | 75参考模板 |
| --- | --- | --- |
| 卖一跨价触发 | 低于67到不低于67美分 | 低于70到不低于70美分 |
| 反转确认价 | 70美分 | 75美分 |
| 最高买价 | 70美分 | 75美分 |
| 四阶段新增份额 | 5、18、54、130 | 5、22、75、236 |
| 用途 | 可一键填入后继续修改 | 可一键填入后继续修改 |

1. 第一阶段接受任一方向有效跨价；之后只有相反方向的新跨价才创建下一阶段。同方向反复跨价不加阶段，采用原文06的明确规则，消除09歧义。
2. 触发、阶段订单、确认反转、实际成交分别计数；不等待旧单成交或确认价才下下一阶段。最多达到用户配置的阶段数。
3. 使用 `BUY GTC, postOnly=false`，首次可立即成交，余量继续挂单。反转不撤旧方向单、不提高最高价、不把部分成交重新整笔提交。
4. 只认交易所真实成交。首次提交可能得到更低价；已挂在70美分的买单不能用后来60美分卖一当自己的成交价。这是原纸面成交假设必须修正之处。
5. 不增加最后20/10秒禁止下单。实际截止停止新增、撤余量、继续处理迟到回报，之后按官方结果结算。
6. 报价年龄不超过2秒、双边源时间差不超过1.5秒；无可信盘口只暂停新触发，不擅自撤正常旧单。重连重建跨价参考，不补造丢失期间的阶段。
7. 无状态中途启动从下一场开始；已有状态恢复当前场。新场首份有效成对盘口若某方向卖一在`[触发价,最高价]`内，允许一次首单，单独记为`initial_band_entry`，不伪造成跨价。双边冲突等待；重启/重连不得重复首样本入场。这与原文01及用户运行日志一致。
8. 一个策略实例只使用一份参数配置。参数保存到服务端，修改触发价、确认价、最高买价、阶段份额或预算默认下一场生效；当前订单按原版本继续管理。网页关闭不影响执行。

| 行情市场 | 规则、token、完整L2、用户WS | 预热下一场并自动换场；旧场订单与结算继续跟踪，不串token |
| 真实订单 | SDK签名、提交/撤单、部分成交 | 保存签名订单身份、未知ACK查原单、离线成交补齐；记录撤单请求、确认时间和确认耗时，不重复经济订单 |
| 成交账本 | 预留、去重、持仓存储 | MATCHED后FAILED冲正、按市场token对账；不重复扣退资金 |
| 费用资金 | 余额/持仓读取、费用预留 | 当前市场费率、真实扣费资产、预留与真实费用分开；现金持仓相符 |
| 官方结算 | 结果/赎回接口、calldata编码 | 接钱包或relayer sender、回执及实际到账；只有 confirmed 且 payout_verified 才显示到账，广播不算完成 |
| 运行API | 启停、状态和日志投影 | 策略注册、配置版本、真实启停、场次、统一订单分页 |
| 前端 | 六入口、账户和遥测组件 | 去做市、反转状态、普通配置、订单10/20/50分页 |

评估时发现的旧场健康拦截、新旧场订单混比、FAILED遗漏、赎回sender未接线和固定费用估算问题已经修复。本批新增撤单 ACK 遥测、到账证明投影和预算不足提示，已随 `70d2b55` 发布。具体原问题见技术评估6.1；当前剩余项以本规划和 CURRENT-STATUS 为准，不要求等待更多天数据。

官方文档核验新增要求：部分涨跌市场 `itode=true` 有250ms主动成交等待，必须记录该市场标记，不能把全部ACK耗时归因代码；GTD有最短有效时长约束，首版采用GTC加截止撤单；MATCHED不是最终链上确认。官方链接及核验日期见技术评估第10节。

## 4. 接口与速度

以下是当前实现采用的能力契约，复用现有API风格，不另造框架。

| 能力 | 必要字段或行为 |
| --- | --- |
| 策略配置 | strategyId、可编辑字段定义、参数模板（可选）、savedRevision、activeRevision、nextRoundRevision |
| 启停 | 策略/配置版本/模式；返回真实实例与进程。暂停新增保留运行与结算；停止撤余量并退出，已有持仓保留，下次启动恢复 |
| 场次状态 | conditionId、tokens、start/end、阶段1–N、触发方向、确认方向、订单归属、持仓、原因、版本 |
| 订单列表 | 实例/场次/状态筛选、limit=10/20/50、offset及固定事件快照；真实orderId一单一行，fills展开；撤单请求/ACK/耗时独立显示 |
| 场次收益 | 官方结果、实际成本/费用/持仓、预计返还、赎回状态/txId、到账验证、实际到账和净结果；未知数据不补零 |
| 实时推送 | WS或SSE序号/行情/订单更新；断流补快照。浏览器轮询不参与交易决策 |

热路径：`行情事件 -> 本地跨价与阶段判断 -> 持久化意图/预留 -> 签名提交`。用户回报即时更新账本，全量账户、历史查询、页面刷新放后台；重启或未知提交才做针对性恢复，不能每笔先串行远程查四遍账户。

业务唯一键为 `instance + conditionId + stage`。本地clientOrderId不等于官方查询键；保存已签payload/hash和返回orderId，超时先查同一单。一次404或开放订单列表缺失不能证明原单未成交。

分别展示消息年龄、本地计算、持久化、签名、HTTP ACK和认证回报。本地事件处理目标p95在20ms内，磁盘与网络单独实测；不承诺交易所毫秒ACK，也不把等待对手方成交算作代码处理延迟。

## 8. 必须完成的验证

1. 新场首样本区间入场一次；后续跨价只触发一次、同向不加阶段、对向可独立创建、不超过配置的阶段上限、尾盘无自创禁入规则。
2. 部分成交仅管理余量，反转不撤旧单；旧单和新单并存，真实费用不按盘口猜。
3. 超时、ACK前成交、重复/迟到/FAILED回报、断线中成交及重启，均不重复下单/扣款。
4. 换场不串token/版本，旧场过期不拦新单，旧场占用与待到账不重复使用。
5. 小额真实订单完成ACK、至少一笔实际成交、独立挂单撤销、认证回报、重启查回及账户核对。不使用自己账户对敲制造成交。
6. 至少一笔赢家持仓走官方结果到实际赎回到账；可用已有合适持仓验证。没有到账回执就保留未通过状态。
7. 配置刷新不丢、分页不重不漏、真实停止有效；桌面/手机截图确认内容不溢出。

短时自动化测试检查软件行为，不是策略回测或模拟观察。运行受影响测试、类型检查及构建；跨模块再跑集成回归。不用既有60项底座测试通过冒充新策略验收。

[用户既有运行日志](evidence/2026-09-17/reference-strategy-log-70.md)已纳入：首样本入场、旧单等待、部分成交50/130、反转5次但仅4单等场次直接用于功能用例。其纸面成交不替代真实ACK/成交回报，历史71美分执行与当前70上限分版本，不增加回测或观察等待。

## 9. 资金配置

这是一个策略实例，所有价格、阶段份额、最大阶段数、单场预算、总预算、日内停止条件和运行时长都由用户在策略页填写并保存。70 与 75 的数值只作为可一键套用的历史参考模板，用户可以继续修改，系统不能把它们当作固定方案、第二个策略或上线门槛。

资金检查使用用户当前填写的预算和交易所实时规则：下单前按当前价格、最小数量、实际费率和未结算占用计算需要的可用资金；不足时只阻止超出预算的阶段，并明确显示原因。不会把历史样本的 147.94/257.94 美元测算写成固定要求，也不会在服务端偷偷替换用户参数。预留费用与最终实际费用分开记账，预算变更默认下一场生效。

真实接口验证先使用交易所允许的最低有效金额，逐项验证认证、限价提交、ACK、挂单、撤单、部分成交、用户频道、重启恢复、账户变化和结算回执。金额可以按用户配置逐步提高；小额测试结果只证明接口和生命周期行为，不宣称已经完成任意高份额配置或保证盈利。测试允许出现可控小额损失，但不能跳过未知订单、重复下单、资金守恒和官方结算核对。

页面同时显示用户预算、已用、冻结、未决提交、未结算占用、剩余可用资金和实际已实现结果。日内停止条件是用户可选的新增风险控制，不会抹掉已经成交的持仓风险；若用户不设置则显示“未设置”，不伪造默认额度。日内权益和资金活动可恢复时按真实记录计算，无法恢复的范围明确显示，不以等待午夜作为开发前置。
