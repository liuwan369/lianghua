## 已完成的公共功能

- `TradingPlatform`：市场、深度行情、账户读取、订单、持仓、风险、结算、历史和遥测的统一 façade。
- 新平台执行边界：`StrategyPlugin` 和 `trading-platform` CLI 通过 `TradingPlatform.orders` 调用提交、撤单、替换和批量撤单；签名由 `PolymarketGateway` 负责，资金和状态由 `TradingCore` 负责。现有控制台启停和旧 CLI 尚未迁入这条路径。
- `TradingCore`：BUY/SELL 资金与份额预留、部分成交、撤单、替换、重复成交去重、账户快照时间顺序、风险停机和持久化状态；已覆盖 paper 立即成交与撤单回调竞态。
- `StrategyPlugin`：策略只能读取只读上下文并返回 `submit/cancel/replace` 意图，不能直接访问 CLOB 客户端或修改账本。
- `PaperGateway`：独立模拟执行，支持显示深度、公开成交驱动的 maker 成交、FOK/FAK、部分成交和撤单回报；已保证提交 ACK 后的已成交事件先于撤单状态到达核心。
- Polymarket 适配器：真实市场规则、CLOB 签名、用户 WebSocket、订单/成交事件、账户读取和定向结算接口。
- `PlatformStore`：按账户和模式持久化状态，带独占锁、临时文件、`fsync` 和崩溃锁恢复。
- 深度和延迟字段：完整 L2 档位、交易所时间、本机接收时间、处理耗时、消息年龄、签名和 ACK 耗时。
- 通用 CLI：`trading-platform` 默认 paper，只有显式 `--live` 才连接真实网关；没有策略时只运行平台。

## 尚未完成的公共功能

- 控制台启停、进程恢复和状态/日志投影迁入新平台。现有“开始模拟”仍调用旧 `live.js run`；策略暂停目前是停止运行状态和开发约定，尚不是后台禁止旧入口的开关。
- 真实适配器的部分成交、撤改竞态、断线中成交、异常恢复和长期连续运行样本。
- 账户余额、在途订单、持仓、费用、结算和外部资金变化的持续联合核对。
- 结算到账和奖励付款的完整钱包对账。
- 五档深度、订单生命周期分段延迟和自动调整原因接入现有控制台展示。
- 服务器采集器恢复后的连续延迟和资源稳定性样本。

## 策略状态

旧 `Engine/MakerSession/PairCost` 路径和历史 paper/真实探针只作为兼容代码与证据保留。它们不属于新的公共底座验收，也不代表策略已经盈利或可以自动实盘。新的策略统一实现 `StrategyPlugin`；策略研究、参数选择、默认值和收益评估全部延期到公共底座审查完成后。

## 验证基线

最近一次 TypeScript 验证为 43 个测试文件、418 项测试全部通过，`npm run typecheck` 和 `npm run build` 通过；前端 8 个文件、64 项测试及构建通过。新增覆盖失败核对不修改账本、FAK 撤单后不再撮合、并发提交/撤单和回调重入。该结果证明代码在测试样例下满足契约，不等于真实资金或盈利验收。
