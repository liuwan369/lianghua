## 已核对的软件约束

| 范围 | 当前行为 |
| --- | --- |
| 资金钱包与协议 | canonical funder 优先；EOA 不得代替不同 Deposit Wallet approve/settle；版本严格为数值 2 |
| 预算与份数 | 费用、首腿裸仓最坏损失、有效挂单及待撤占用进入最终检查；裁剪后再次验成本；最低份数不足拒绝，不自动扩大 |
| 吃单 | 固定份数 FOK；吃单未终态期间冻结新提交，不能重复花费待处理预算 |
| 部分成交/迟到回报 | 保留剩余挂单量与本次订单 ID；旧单回报不清新单，REST 正确识别本方 maker BUY |
| 连接 | 异常 ACK 不算成功；WS 认证失败立即不健康；空盘口清旧报价，旧 BBO 不覆盖新深度 |
| 停止 | 冻结新提交、等待在途 ACK、撤单、两次空挂单确认、稳定读取最终成交、补写晚成交后关闭 feed |
| 最终对账 | 只接本次已知订单，稳定 ID 去重；不遗漏已有成交再清空库存；失败不标正常完成 |
| 控制服务 | 实盘停止等待 8 秒后保留未完成进程并返回等待状态，同 PID 不重复 SIGTERM，不超时强杀截断对账 |
| 前端与参数 | 历史运行选择不妨碍新运行发现；旧启动接口拒绝 null、对象、bool、字符串和非有限/溢出数值 |

默认策略参数数值未因这些修复改变；预算/费用/份额约束更严格时订单可缩量或拒绝，旧结果不能直接作为当前收益证据。

## tick 与回测输入

每个 token 的真实步长来自官方元数据/公开接口，WS 更新按时间排序；缺步长拒绝 maker，不默认 0.01。策略、概率过滤、预算和执行先向下量化再验成本，拒绝原因变化写入 `decision_rejected`。

回归场景 `UP 20 @ 0.23`、`DOWN 0.76/0.77`：tick=0.01 时可按 0.76 补腿；tick=0.001 时价格 0.761 仍超 0.99 上限而拒绝。历史回测要求每侧真实 tick，缺失/冲突/非法时间直接报错；不带时区的旧格式按 UTC，已有 ISO 时区保持语义。见 [历史数据要求](BACKTEST-TICK-DATA.md)。

## 最终版本真实行情 paper

90 秒 paper 使用无交易密钥的清洁环境，含启动共 106.72 秒、exit 0。记录 1 个市场、1 笔报价、1 笔模拟成交 `DOWN 20 @ 0.18`、35 条变化后的 `hedge_pair_cost` 拒绝及正常停止。两侧实际 tick=0.01，没有缺 tick 拒绝。

$3.60 是停止时未配对、未结算的模拟持仓成本，**不是已结算亏损**。最初补腿成本 `0.18+0.83=1.01`，超过 0.99，之后价格更差。证明已获取真实 tick、生成报价、纸面记账及解释拒绝；没有证明完整对冲、实盘或盈利。

`target_clone` 启用动态补腿。候选普通阈值会随裸仓时间从 0.99 放宽至最多 0.999，裸仓超过 30 秒或距结算不足 75 秒可使用紧急候选阈值 1.05；最终动态份数和裁剪后成本仍受 `hedgePairCostCeiling=0.99` 约束。因此“紧急/强制”不能理解成一定成交的退出机制。
