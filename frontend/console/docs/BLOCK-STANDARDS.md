# 区块标准清单

这份文档回答一个之前没被问过的问题:**每个界面区块存在的目的是什么,达到什么程度才算合格。**

之前的审计是"字段级验证"——读代码、对 API、确认数据通了。它能抓到「NO 份额显示 0」这类矛盾,但抓不到「运行日志把 `account_recovery_started` 标成异常并刷 16 条」这类问题,因为那不是字段错,而是**功能没达到它本该达到的标准**。

每个区块按三项定义:**目的**(解决操作员什么问题)、**合格标准**(必须能回答哪些具体问题)、**误导风险**(什么情况下它会让人做出错误判断)。

判定:✅ 达标 · ⚠️ 部分达标 · ❌ 不达标

---

## 总览页

### 交易统计(订单数 / 盈亏 / 胜率 / 累计盈利)

**目的**:一眼判断"在赚钱还是亏钱,成本吃掉多少"。

**合格标准**
1. 净盈亏必须和手续费分开显示,并能看出费用占比
2. 胜率必须暴露分母(`1 / 1` 而非只有 `100%`)——小样本的高胜率不能显得像稳定盈利
3. 未结算、无法核实的场次要单独计数,不能混进胜负
4. 金额单位、精度一致;不确定的值显示 `--` 而不是 0

**现状 ⚠️**
- 手续费只在页脚小字里(`fees=0.30567`),而它占 1.57 盈利的 **20%**——这个量级必须有独立位置
- 胜率显示 `100%` 但样本只有 1 场,极易误读为策略很强
- 「累计盈利」这个名字有歧义:它实际是**已确认结算的净盈亏**,不含未结算场次

**误导风险**:1 场 100% 胜率 + 看不见成本 = 以为策略稳定赚钱。

---

### 服务器状态(CPU / 内存 / 磁盘 / 负载 / 四个服务)

**目的**:判断"机器和服务是否健康,是否需要运维介入"。

**合格标准**
1. 资源指标要能看出趋势,不只是瞬时值(单个数字看不出是否在恶化)
2. 服务状态必须区分"未运行(正常停止)"和"异常退出"
3. 运行时长要可读(`1 天 2 小时` 而非 `88972 秒`)
4. 取不到值时显示 `--`,不能拼成 `--%`

**现状 ✅**(本轮已修:sparkline 趋势、时长格式化、`--%` 修正)

**误导风险**:交易进程"未运行"在正常停止时是预期状态,若标红会造成不必要的紧张。

---

### 运行日志

**目的**:**3 秒内**知道 (a) 系统是否健康 (b) 出了什么事 (c) 要不要干预。

**合格标准**
1. **严重级按语义判定**:`*_started` / `*_completed` 是信息,`*_failed` / `*_timeout` / `*_rejected` 才是异常。不能靠关键词猜
2. **同类事件折叠计数**:重复事件必须合并成一条并显示次数与时间范围
3. **真异常不被淹没**:高频信息类事件不能把唯一的真问题挤出视野
4. **每条能回答"我该做什么"**:要么说明影响,要么说明系统正在自愈
5. **反复重试本身就是异常**:同一恢复动作重试 N 次未成功,要表达"重试中 N 次",而不是 N 条独立"异常"

**现状 ❌**(截图为证)
- `account_recovery_started` 被判为**异常**——名字明确是 started,是信息
- 同一事件 **16 条**刷满整屏,把真正的 `settlement_drain_timeout` 挤到看不见
- 没有表达"重试 16 次仍未成功"这个**最关键的事实**
- 「运行状态已更新 / 来自服务器的运行状态记录」——说了等于没说
- 列表越拉越长,无折叠无分组

**误导风险**:满屏红色"异常"让人以为系统崩了;反过来,真异常被淹没时又会漏掉。两个方向都错。

## 自动交易页

### 交易速度(行情到决策 / 下单确认 / 撤单确认 / 整轮反应)

**目的**:判断"执行链路是否够快,慢在哪一段"。

**合格标准**
1. 明确标注只含代码链路,不含等待对手成交(否则会被误读为成交慢)
2. 无样本时显示 `--`,不显示 0
3. 有基准可参照(什么算正常,什么算慢)

**现状 ⚠️**:有免责说明,但**没有基准值**——看到 `120ms` 不知道算快还是慢。

---

### 当前盘口 / 五档深度

**目的**:确认"行情是否真实可交易,深度是否够吃下计划仓位"。

**合格标准**
1. 五档要真出数(不能有数据却显示空)
2. 明确区分"深度不可用"和"深度为空"
3. 报价过期要明确标注,且不能冒充实时

**现状 ✅**(本轮已修:标量 `bid` 遮蔽 `bids` 数组导致五档全空)

**误导风险**:深度空白会让人以为市场没流动性而不敢下单。

---

### 本场持仓与结果

**目的**:知道"这一场买了多少、成本多少、赢或输会怎样"。

**合格标准**
1. 份额与阶段时间线必须一致(时间线说成交了,份额不能是 0)
2. 均价要说明是否含手续费(含费会高于限价,否则看着像突破限价)
3. 拿不到数据时显示 `--`,不能显示确定的 0

**现状 ✅**(本轮已修:`{}` 假值导致硬报 0;均价标注"含费")

**误导风险**:把"未知"显示成 `0.00` 会让人以为没买到,可能重复下单。

---

### 阶段进度

**目的**:看清"分阶段买入执行到哪一步,还剩几阶段"。

**合格标准**:每阶段的方向、限价、成交/计划份额、状态都可见;有分母(`2 / 4`);跳过与放弃的阶段可区分。

**现状 ✅**(本轮已接;之前永久显示"待接入")

---

## 市场页

### 可用币种

**目的**:选择要交易的币种,并知道为什么某个币种不可选。

**合格标准**
1. 不可选时必须说明**具体原因**(行情过期 / 服务器未支持 / 身份不全)
2. 单个币种的行情问题不能影响其他币种
3. 当前场次与下一场生效要分清

**现状 ✅**(本轮已修:一个币种 stale 曾导致整个目录被判 stale,阻塞其他币种)

---

## 策略页

### 策略参数 / 参数预览

**目的**:配置策略并**在提交前**看清这组参数意味着什么。

**合格标准**
1. 预览要算出总投入和最坏情况成本
2. 三个价格参数的关系必须自解释(触发价 ≤ 确认价 ≤ 最高买入)
3. 排版不能折行/溢出

**现状 ⚠️**
- 排版已修(grid 子项数与列数不匹配)
- **但 `确认价` 实际不参与下单**(只喂一个计数器),界面没有任何提示。用户会以为它是风控闸门——这是**语义层面的误导**,比排版严重

---

## 设置页

### 系统诊断 / 账户状态

**目的**:确认"账户是否就绪可交易,连接是否正常"。

**合格标准**:每项就绪条件独立可见;未就绪要说明如何解决;不回显任何密钥。

**现状 ✅**

---

## 优先级

| 优先级 | 区块 | 问题 |
|---|---|---|
| **P1** | 运行日志 | 严重级误判、事件刷屏、真异常被淹没、未表达重试失败 |
| **P1** | 交易统计 | 手续费无独立展示(占利润 20%)、胜率无分母 |
| **P2** | 参数预览 | `确认价` 不参与下单却无提示 |
| **P3** | 交易速度 | 无基准值,数字无法解读 |

P1 两项是你实际看着最难受、也最容易导致误判的。
